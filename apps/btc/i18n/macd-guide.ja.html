MACDを手計算してみる
— 終値42本を最後まで追うウォークスルー

最終更新：2026-10-10 · 執筆：Y-Systems · この記事は解説ではなく実習の記録です

モデルのバージョンについて — この記事の指標数（6つ）、ウェイト、計算例は、オンチェーン指標2種（MVRV Z・Thermocap Z）を加える前のv1モデルに基づいています。現在のダッシュボードのスコアは8指標を使うv2で、ウェイトも異なります。最新の数値はスコアの算出方法をご覧ください。

まず失敗からお見せします。終値を30本用意して標準のMACD（12・26・9）を回すと、 MACD線は5個出ますが、シグナル線は0個、ヒストグラムも0個です。 1か月分のデータでは、MACDヒストグラムをただの1本も作れません。 この事実を知っている人は意外と少ないものです。MACDを「12日線と26日線の差」程度にしか習っていないからです。

そこでこの記事は定義から始めません。終値42本を実際に代入し、 EMA12 → EMA26 → MACD線 → シグナル線 → ヒストグラム → broodevの部分スコアまで、 電卓を片手に1本ずつ追いかけます。電卓が1つあれば、この記事のすべての数字を自分で再現できます。 再現できなければ、間違っているのは私たちのほうです。

ウォークスルーに入る前に、この記事で扱う計算を実際のBTCデータに当てはめた結果を先に見ておきます。下の終値42本の実習とまったく同じ式（EMA12−EMA26、シグナルEMA9）です。

STEP 1

SMAではなくEMAを使う理由 — 「12日前の足が今日のシグナルを作る」

教科書は「EMAは直近の価格により敏感なので速い」と言って終わります。その一文は半分しか正しくありません。 同じ42本の終値で、SMA版MACD（SMA12−SMA26）とEMA版MACD（EMA12−EMA26）を 並べて回してみました。

結果1 — 底はEMAのほうが1本早かった

EMA版は28日目に底（−7.008）をつけて反転し、SMA版は29日目（−7.201）でした。 1本の差です。しかもEMA側の底のほうが浅い（−7.008 vs −7.201）。 ここまでは教科書どおりです。

結果2 — ところがゼロラインへの復帰はSMAのほうが早かった

42日目を見てください。SMA版は−0.006で事実上ゼロラインを抜けているのに、EMA版はまだ−1.389です。 「EMAは常に速い」という話がここで崩れます。なぜSMAは急に跳ねたのでしょうか？

41日目 → 42日目に、SMA版MACD線は−1.036から−0.006へ、1日で+1.030動きました。 同じ日、EMA版は+0.565しか動いていません。2倍近い差です。計算してみると原因が見えてきます。 

SMA12(42日目) − SMA12(41日目)
  = (新たに入った42日目 86.2 − ウィンドウから外れた30日目 74.3) ÷ 12
  = 11.9 ÷ 12
  = +0.9917          ← 今日の価格ではなく「30日目の足が消えたこと」の効果

SMA26側の変化 = (86.2 − 16日目 87.2) ÷ 26 = −0.0385

SMA版MACDの変化 = +0.9917 − (−0.0385) = +1.030   ✅ 表と一致

これがSMAを使ってはいけない本当の理由です。42日目のSMAシグナルの大部分は、 今日の価格が上がったから生じたのではなく、12日前（30日目）の最安値74.3が移動平均のウィンドウからポンと抜け落ちたから生じたものです。 今日の市場では何も起きていないのに、12日前に起きたことが今日の買いシグナルを作るのです。 業界で「ドロップオフ効果（drop-off effect）」と呼ばれる現象です。

EMAにはウィンドウがありません。古い価格のウェイトは(1−α)ⁿで指数的に少しずつ消えていくだけで、 ある日突然計算から追い出されることはありません。だからEMA版は同じ日に+0.565と滑らかに動きました。

まとめると — EMAを使う理由は「速いから」ではなく「幽霊シグナルを作らないから」です。 SMAは転換点で1本遅れる代わりに、とんでもないタイミングで12日前の足が作った偽の急変をばらまきます。 シグナルの速さよりも、シグナルの原因のほうが重要です。

STEP 2

EMA12を電卓で叩いてみる

broodevが使うEMAは、最初のperiod本の単純平均をシード（seed）にし、そこから指数的に更新していく方式です。 α = 2 ÷ (期間 + 1)です。EMA12ならα = 2/13 = 0.153846。 

// broodev の実際のコード (apps/btc/app.jsx)
function ema(values, period) {
  const alpha = 2 / (period + 1)
  let seed = 0
  for (let i = 0; i < period; i++) seed += values[i]
  let prev = seed / period          // ← シード = 先頭 period 本の単純平均
  out[period - 1] = prev
  for (let i = period; i < values.length; i++) {
    prev = values[i] * alpha + prev * (1 - alpha)
    out[i] = prev
  }
}

では上の終値42本を入れます。12日目にシードが1つでき、13日目から更新が始まります。

12日目のシード = (100.0 + 99.1 + 100.4 + ... + 91.7) ÷ 12
              = 1162.7 ÷ 12 = 96.8917

13日目 = 90.3 × 0.153846 + 96.8917 × 0.846154 = 95.8776
14日目 = 91.1 × 0.153846 + 95.8776 × 0.846154 = 95.1426
15日目 = 88.6 × 0.153846 + 95.1426 × 0.846154 = 94.1360
16日目 = 87.2 × 0.153846 + 94.1360 × 0.846154 = 93.0689
17日目 = 88.0 × 0.153846 + 93.0689 × 0.846154 = 92.2891

要点は「昨日のEMAの84.6%に、今日の終値の15.4%を足す」、ただそれだけです。 ウェイトは毎日同じで、過去は毎日84.6%ずつ薄まっていきます。30日前の終値のウェイトは 0.153846 × 0.846154³⁰ ≈ 0.0009 — 0.1%にも届きません。でもゼロではありません。この差がSTEP 1の結論でした。

STEP 3

EMA26とMACD線 — 26日目にようやく最初の値が出る

EMA26はα = 2/27 = 0.074074。シードは1〜26日目の単純平均です。

26日目のシード = 2341.4 ÷ 26 = 90.0538
27日目 = 76.4 × 0.074074 + 90.0538 × 0.925926 = 89.0425
28日目 = 75.1 × 0.074074 + 89.0425 × 0.925926 = 88.0097
29日目 = 76.0 × 0.074074 + 88.0097 × 0.925926 = 87.1201
30日目 = 74.3 × 0.074074 + 87.1201 × 0.925926 = 86.1704

EMA26のシードが26日目に初めてできるので、MACD線（EMA12 − EMA26）の最初の値も26日目です。 25日目まではMACD線そのものが存在しません。 

MACD線(26日目) = EMA12(83.106) − EMA26(90.054) = −6.948

STEP 4

シグナル線 — ここが30本では足りない地点

シグナル線はMACD線のEMA9です。つまりEMAのEMAです。 MACD線は26日目から始まるので、シグナル線のシード（MACD線9個の平均）は 26日目から34日目までが全部そろって初めて作れます。 

シグナルのシード(34日目)

    −6.6404 −6.4634 −6.0835 −5.6129) ÷ 9

ヒストグラム(34日目) = MACD線(−5.613) − シグナル線(−6.6071) = +0.994   ← 最初の値！

       ヒストグラム = −5.2360 − (−6.3329) = +1.0969

なぜ30本ではヒストグラムが0個なのか
26（EMA26のシード）+ 9（シグナルのシード）− 1 = 34。ヒストグラムの最初の値はどんなに早くても34本目です。 しかもbroodevはヒストグラムの前日比の変化を見るので、2個必要です → 35本。 だからコードにこのガードがあります。 
if (closes.length >= 35) { ... }   // ← 35本未満なら MACD 部分スコア = null
MACDがnullならウェイトの再正規化が働き、 残り5つの指標でスコアを出してcoverage 5/6と表示します。新規上場コインでよく見かける状態です。

付け加えると、35本は必要条件であって十分条件ではありません。34日目のヒストグラムは、シグナルのシードが MACD線9個の単純平均なので、まだ「半煮え」の値です。実戦で安定したヒストグラムを見るには、 少なくとも60〜80本は積み上がっている必要があります。この問題はこの記事の最後の付録Aで数字とともに改めて扱います。

STEP 6

ここでbroodevは教科書と分かれる — 絶対値ではなく方向

ここまでは標準のMACDでした。どのチャートソフトでも同じ値が出ます。 ここからがbroodev独自の部分です。ヒストグラム（範囲の決まっていない実数）を 0〜100のスコアに変える関数を、ソースそのまま公開します。 

// 短期（モメンタム）マッピング — MACD ウェイト 14%
const momMacd = (cur, prev, px) => clamp(
    50
  + 30 * tanh( (cur / px)          * 800 )    // ① ヒストグラムのレベル
  + 15 * tanh( ((cur - prev) / px)  * 800 )    // ② 前日比の方向
, 0, 100)

// 長期（逆張り）マッピング — MACD ウェイト 18%
const conMacd = (cur, prev, px) => clamp(
    50
  + 25 * tanh( ((cur - prev) / px)  * 600 )    // ② 前日比の方向
  + 10 * tanh( (cur / px)          * 600 )    // ① ヒストグラムのレベル
, 0, 100)

2つの関数は構造が同じで、係数が逆になっています。それがすべてです。

項意味短期（モメンタム）係数長期（逆張り）係数
① レベル今のヒストグラムがどれだけ大きいか（絶対値）3010
② 方向前の足より大きくなったか小さくなったか（Δ）1525
レベル：方向の比率2 : 11 : 2.5
tanh ゲイン大きいほど小さな変化で早く飽和する800600

短期モードはレベルを2倍重く見ます。トレンドがどれだけ強いかが重要だからです。
長期モードは方向を2.5倍重く見ます。ヒストグラムがまだ深いマイナスでも、 「昨日より良くなったか」がスコアを支配します。

1行目と2行目を比べてください。ヒストグラムの値は−0.30でまったく同じです。方向だけが違います。 それなのに長期部分スコアは22.6 → 58.4と35.8点も開きます。 絶対値だけを見るモデルなら、この2つの状況は区別できません。どちらも「悪い」です。

ところが1行目は、STEP 3で見たまさにあの28日目です。 価格が安値を更新していた瞬間、下落圧力が弱まり始めたまさにその足。 絶対値だけを見ていたら、その足を「最悪」と採点していたでしょう。実際には底の2本前でした。

3行目と4行目は逆方向の同じ話です。ヒストグラムがプラス（+0.10）なので絶対値モデルにとってはどちらも「良い」ですが、 一方は折れ始めていて、もう一方は上昇中です。長期スコアは37.5 vs 66.5に分かれます。

一言でいえば — ヒストグラムの絶対値は「今どれだけ良いか」を語り、 前日比の変化は「これから良くなりつつあるか」を語ります。 長期の積み立てという観点で私たちが買いたいのは、すでに良くなった資産ではなく悪化が止まった資産です。 だから長期マッピングでは方向係数（25）がレベル係数（10）を圧倒しているのです。

代償：tanhはすぐに飽和する（41日目の教訓）

タダのものはありません。方向を重く見ると、ごく小さなノイズにもスコアが大きく揺れます。 STEP 5の表の41日目がその証拠です。 

40日目: Δヒストグラム = +0.155  (価格 84.7 比 +0.183%)  → 長期スコア 80.0
41日目: Δヒストグラム = −0.014  (価格 83.9 比 −0.017%)  → 長期スコア 57.4

方向項の計算:
  40日目 → 25 × tanh(600 × 0.00183)  = 25 × tanh( 1.098) = +20.0
  41日目 → 25 × tanh(600 × (−0.00017)) = 25 × tanh(−0.100) = −2.5
  差 −22.5点   ← 長期部分スコアの下げ幅（−22.6）と一致

価格の0.017%にあたるヒストグラムのわずかな低下ひとつで、長期部分スコアが22.6点下がりました。 原因はtanhの飽和です。tanh(1.098) ≈ 0.80 — つまりΔが価格のわずか0.18%になっただけで、 方向項はすでに最大値（25点）の80%を取ってしまいます。それ以上はいくら大きくなってもほとんど上がりません。 逆に符号が変わると、その20点は即座に消えます。

この飽和カーブを表にすると一目瞭然です。

では最終スコアはどれだけ揺れるのか

MACDは6つの指標のうちの1つにすぎません。ウェイトを掛けて総合スコア（0〜100）への実際の影響を計算すると。

短期モード: 部分スコアの幅 61.9 × ウェイト 0.14 = 8.67点
長期モード: 部分スコアの幅 38.4 × ウェイト 0.18 = 6.91点

ここで直感に反する結果が出てきます。 短期はウェイトが軽いのに（14% < 18%）、最終スコアはより大きく揺れます（8.67 > 6.91）。 レベル係数30とゲイン800が、短期マッピングをはるかに敏感にしているからです。 ウェイトだけを見て「短期はMACDをあまり重視しない」と結論づけると間違えます。マッピング関数まで見る必要があります。

ちなみに両モードとも平均は50付近（52.6 / 50.7）です。レンジ相場でMACD部分スコアは 平均的には中立を保ちます。問題は、平均ではなくその日その日の値で売買するということです。

STEP 8

ウェイト14% vs 18% — 計算で答える

算出方法のドキュメントで公開しているウェイトでは、MACDは短期14%、長期18%です。 「モメンタム指標であるMACDが、なぜモメンタムモード（短期）のほうで軽いのか？」 — よく受ける質問で、もっともな質問です。 答えは重複（redundancy）です。

モードモメンタム・トレンド系逆張り系MACDの役割
短期 RSI 28% + F&G 28% + 下落率 18% + MACD 14% + クロス 8% = 96%
短期モードではRSI・F&G・下落率がすべてモメンタム方向にマッピングされる		 マイヤー 4% 重複。すでに96%がトレンドを見ている
長期 MACD 18% + クロス 14% = 32% F&G 18% + マイヤー 18% + 下落率 14% = 50%
（RSI 18%は逆張りマッピング）		 唯一のブレーキ。68%が「買え」と叫ぶときに止める32%の半分以上

短期モードの6指標は、事実上5つがすでにモメンタム方向にマッピングされています。 RSIは50 + (RSI−50) × 1.6で高いほど高得点（買われすぎ = 良い）、 F&Gも強欲なほど高得点、下落率も浅いほど高得点です。 ここにMACDを重く載せると、同じ情報を4回数えることになります。 しかもSTEP 7で見たように、MACDはこのセットで最もノイズの多い指標です（27本で10回反転）。 ノイズの多い重複指標にウェイトを上乗せする理由はありません。だから14%なのです。

長期モードは正反対です。F&G（18%）・マイヤー（18%）・下落率（14%） — 合わせて50%が逆張り指標で、 この3つは下落相場でそろって外れます。3つとも「安い、買え」と叫ぶのに、価格は下がり続けます。 このとき「まだだ」と言ってくれる指標は、MACD（18%）とゴールデン/デッドクロス（14%）だけです。 ところがクロスは200日移動平均を使う最も遅いシグナルなので、底値付近では数週間遅れます。

結論 — 長期モードでのMACD 18%は、「モメンタムをより信じているから」ではなく「ブレーキが足りないから」です。 逆張り3兄弟が50%を占める構造の中で、トレンドが本当に転換したかを確認してくれる唯一の速い指標がMACDです。 そしてその確認は、ヒストグラムがプラスになったか（遅い）ではなく ヒストグラムが昨日より大きくなったか（速い）で行われます — だから長期マッピングの方向係数は25なのです。 ウェイト18%と方向係数25は、同じ決定の2つの顔です。

付録A

あなたのチャートと私たちのヒストグラムは違うかもしれない

これは大半のMACD記事が決して言わない事実です。MACDは標準規格ではありません。 「12・26・9」は決まっていますが、EMAの最初の値を何から始めるか（シーディング）は決まっていません。

  • broodev方式 — 先頭period本の単純平均をシードに使う（上のSTEP 2・3）
  • もう一つのよくある方式 — 最初の終値そのものをシードにして1日目からEMAを回す

まったく同じ42本の終値、まったく同じ12・26・9なのに、ヒストグラムはこれだけ分かれます。

同じ性質が弱点でもあり強みでもある
tanhの飽和は極端な値の大きさの情報を捨てます（STEP 6の欠点）。ところがまさにその性質のおかげで、 シーディング方式やデータソースの違いといった実装上のノイズにも、スコアがほとんど揺れません（付録Aの長所）。 一つを得れば一つを失います。私たちは頑健さのほうを選びました。それが正しい選択だったかどうかはわかりません。

ただし、安心するのはまだ早いです。上の結果は、ヒストグラムがすでに大きいトレンド区間の話です。 ヒストグラムが0付近のとき（= 飽和する前）に同じ0.30%の差を入れると、こうなります。

ヒストグラムがゼロラインをはさんで分かれると、短期部分スコアは50点開きます。 そして0付近は、まさに人々がシグナルを探す場所です — 転換点、レンジ相場、クロスの直前。 シーディングの違いが最も問題になる区間が、よりによって最も重要な区間なのです。 （ここでも長期マッピングは短期よりはるかに揺れが小さいです：+14.3 vs +50.0。レベル係数が10しかないためです。）

実戦での3つの示唆
  • MACDの絶対値をサイト間で比べないでください。broodevのヒストグラムがあなたのチャートソフトと 違って出ても、どちらかが間違っているのではなくシーディング方式が違うだけです。比較そのものに意味がありません。
  • データが浅いほど注意してください。新規上場コインはシードの影響がまだ抜けていません。 BTCのように数百本が積み上がった資産では、差は無視できる水準です。
  • 「ヒストグラムがたった今ゼロラインを超えた」というシグナルは特に疑ってください。上の表のとおり、 ゼロライン付近は実装の違いが部分スコアを最大50点も分ける区間です。 ゼロライン突破そのものより、複数の足にわたる方向の持続性を見るほうがはるかに安全です。

付録B

このウォークスルーが証明できなかったこと（そして、できないこと）

ここまで42本・60本の架空データで計算過程を再現してきました。 この記事が証明したことと証明していないことをはっきり区別しておきます。

証明したこと

  • broodevのMACD計算は標準の12・26・9であり、上の数字で誰でも再現できる。
  • ヒストグラムは34本目から、方向の判定は35本目から可能。だからcloses.length >= 35のガードがある。
  • 長期マッピングは方向係数25 : レベル係数10で、方向を2.5倍重く見る。これはコードにそう書いてある。
  • スコアは価格の規模に対して不変である（×700しても小数第4位まで同じ）。
  • レンジ相場でこの指標は27本で10回シグナルが反転する。これは私たちのモデルの実測された弱点である。
  • MACDは標準規格ではない。シーディング方式を変えるだけで、同じデータでもシグナルの発生日が変わる。 ただしtanhの飽和のおかげで、トレンド区間ではその差は部分スコアにほとんど波及しない（0.2〜4.9点）。 ゼロライン付近では最大50点まで分かれる。

証明していないこと（重要）

  • 「方向転換を見れば利益が出る」という証明ではありません。上の42本は私が反発するように作った架空データです。 底で方向転換が出たあとそのままさらに−40%下がるデータを作るのも、同じくらい簡単です。 計算過程の透明性と予測力は、まったく別の問題です。
  • MACDは本質的に遅行指標です。移動平均の差の移動平均なのですから。 ヒストグラムが向きを変える頃には、値動きの一部はすでに過ぎ去っています。 STEP 3でMACD線が価格より2本早く反転したのはダイバージェンスであって予知能力ではありません — そしてダイバージェンスはよく失敗します。
  • ウェイト14%/18%は筆者の判断です。STEP 8の論理（重複の回避・ブレーキの確保）は説得力のある設計上の根拠であって、 最適値の証明ではありません。16%のほうが良いかもしれません。データはきっぱりとは答えてくれません。
  • tanhの飽和で極端な情報を捨てています。STEP 6で見たように、ヒストグラムが価格の0.4%を超えると、 それ以上の大きさはスコアに反映されません。歴史的な大暴落・大暴騰の強さの情報を意図的に捨てる設計です。
  • MACDはニュース・規制・ハッキング・流動性をまったく知りません。取引所が破綻している最中でも、ヒストグラムはきれいに上向きに転換しうるのです。

MACD部分スコアは、broodevの総合スコアの14〜18%にすぎません。 残りの82〜86%はほかの5つの指標が占め、 その合成方法は算出方法のドキュメントですべて公開しています。 どの単一の指標も、単独では何も決めません。それが設計の意図です。
