莱特纳 · SM-2 · FSRS，以及我们为什么不用算法 · 最后更新：2026-07-14 · 作者：Y-Systems

1972 — 莱特纳：“挪动盒子，本身就是算法”

那个时代想解决的问题

那时没有计算机。德国记者塞巴斯蒂安·莱特纳（Sebastian Leitner） 在1972年的著作中提出的，是无需计算的间隔重复。 不需要铅笔，也不需要推算日期。物理上挪动卡片这个动作本身，就是状态的保存。

怎么解决的

  • 把带隔板的盒子分成5格。
  • 所有新卡都从第1格开始。
  • 答对了就向前移一格。
  • 答错了，不管原来在第几格，一律跌回第1格。
  • 每一格的复习周期不同。常见的安排如下。
格复习周期在这一格的含义答错时
第1格每天还不会 / 刚答错留在第1格
第2格每2天答对过一次→ 跌回第1格
第3格每4天连续答对两次→ 跌回第1格
第4格每8天连续三次→ 跌回第1格
第5格每16天基本记住了→ 跌回第1格

严格来说，莱特纳的原始方案不是按日期，而是“格子满了就清空”的容量制。 上面的1·2·4·8·16天是后来固定下来的日历版。 很多文章把这两者混为一谈，所以在此说明。

哪里出了问题

莱特纳的致命弱点是“跌落太残酷”。 一张在第5格只失手一次的卡片，会和“一次都没答对过的新卡” 受到完全相同的待遇，跌回第1格。 实际上那张卡几乎已经记住了，但盒子没有办法表达这一点。 状态只有一个整数，所以没有地方存放“基本记住了，只是今天有点混淆”。

而且所有卡片都爬同一架梯子。 简单的单词也得把5格走完，怎么也记不住的单词同样是5格。 人们需要的是每张卡以不同速度攀爬的梯子。它在15年后出现了。

1987 — SM-2：把整数换成实数的15年

那个时代想解决的问题

波兰的彼得·沃兹尼亚克（Piotr Woźniak）在开发SuperMemo时发表的 SM-2，把莱特纳的“格子编号（整数）”换成了“难易系数（实数）”。 核心发明只有一个：EF（Easiness Factor，难易系数）。

怎么解决的 — 实际公式

SM-2在每次复习时让你自己按q = 0~5六个等级打分（5 = 完美，0 = 一片空白）。然后这样更新EF。

EF' = EF + ( 0.1 − (5−q) × (0.08 + (5−q) × 0.02) )
EF 初始值 = 2.5   ·   EF 下限 = 1.3 (不会再往下降)

这个公式实际给出的值如下。这是手算填出来的表。

q（自评）含义EF 变化量从 EF 2.5 开始
5完美想起+0.102.60
4答对了，但犹豫了一下±0.002.50（不变）
3勉强答对−0.142.36
2答错了，但看到答案就明白−0.322.18
1答错了，看了答案也觉得陌生−0.541.96
0完全空白−0.801.70

q=4 恰好为0，正是这个公式的设计意图。 “顺利答对”是不改变难度评估的中立点， 比它好就上调，比它差就下调。常数 0.1 · 0.08 · 0.02 不是从理论推导出来的，而是沃兹尼亚克手工调出来的值。这一点后面会变得很重要。

接着这样确定下一个间隔。

I(1) = 1天
I(2) = 6天
I(n) = I(n−1) × EF        (n ≥ 3)

若 q < 3 → 把重复次数 n 重置为 1 (间隔回到1天)

EF是乘法倍数。所以EF 2.5的简单卡和EF 1.3的地狱卡 会呈指数级拉开差距。复习次数相同，达到的间隔却完全不同。

复习轮次EF 2.5（简单卡）EF 1.9（普通）EF 1.3（地狱卡）
第1次1天1天1天
第2次6天6天6天
第3次15天11天8天
第4次38天22天10天
第5次94天41天13天
第6次235天78天17天
第7次587天（1.6年）148天22天

到第7次时是587天对22天 — 相差27倍。 这就是SM-2胜过莱特纳的地方。它把简单卡一次收起一年半，眼不见为净， 把这些时间全部用在难卡上。

哪里出了问题

① 六级自评对人来说太难了。 每张卡都要判断 q=3 和 q=4 到底差在哪里。实际上大多数用户 只会反复按其中两三个等级。六级设计实际上塌缩成了三级。

② 失败时的处理含糊不清。原文说“若 q<3，不改变EF，从头开始重复”， 可同一份文档里的伪代码却对所有 q 都更新EF。不同实现的解读各不相同。 一个用了30多年的算法，其核心分支在文档上竟然是含糊的——如实写下来才算诚实。 （本文的模拟采用了“EF也更新”的解读。）

③ 常数没有依据地被固定下来。为什么 I(2) 是6天？为什么偏偏是 0.08？ 1987年一个人用自己的数据手工调出的数字，被原封不动地套用到全世界所有学习者身上。 这就是FSRS出现的原因。

Anki的变体 — 以及“ease地狱（ease hell）”

Anki并没有原样使用SM-2。它把等级减为四个（Again / Hard / Good / Easy）， 把EF称为ease，并重新调整了调节幅度。以默认预设为准，实际行为如下。

按钮ease 变化下一个间隔备注
Again（失败）−0.20上一个间隔 × 0% → 最少1天
（+ 重新学习10分钟）		间隔被打回谷底
Hard−0.15上一个间隔 × 1.2与ease无关的固定倍数
Good±0.00上一个间隔 × ease中立点（相当于SM-2的 q=4）
Easy+0.15上一个间隔 × ease × 1.3简单奖励

其他默认值：学习步长 1m 10m · 毕业间隔 1天 · 简单间隔 4天 · 起始 ease 2.50 · ease 下限 1.30 · 难记卡（leech）阈值 失败8次。 Anki的默认值可能因版本和预设而不同，请在牌组选项中亲自确认。

所谓“ease地狱” — 反复按Again（−0.20）和Hard（−0.15）的卡片， ease会粘在下限1.30上下不来。这样一来，下一个间隔每次只能× 1.3地增长， 1天 → 2天 → 3天 → 4天……龟速爬行。而且Again还会把间隔再次打回1天。 结果就是少数几张卡永远霸占每天的复习队列。
能提高ease的途径只有Easy（+0.15）一个，可你根本不会对地狱卡按Easy。 往下的门有四扇，往上的门只有一扇——这就是SM-2家族的结构性缺陷， 也是Anki用户说“8张难记卡毁了我的人生”的原因。

对策大多在算法之外。删掉卡片、拆分卡片、给它加上例句（“是卡片不好， 不是我笨”），或者手动重置ease。 这意味着人在亲手修补算法修不好的东西，而正是这种自觉催生了下一代。

FSRS — 唯一能准确回答“S到底是什么”的算法

FSRS（Free Spaced Repetition Scheduler）抛弃了手工调参的常数， 用你实际的复习日志来拟合参数。它的基础是DSR模型。

  • D（Difficulty，难度） — 这张卡本质上有多难
  • S（Stability，稳定性） — 记忆能维持多久
  • R（Retrievability，可提取性） — 此时此刻能想起来的概率

它这样定义遗忘曲线（以FSRS-4.5 / 5为准，DECAY = −0.5，FACTOR = 19/81）。

R(t, S) = ( 1 + (19/81) × t/S ) ^ (−0.5)

这里有一个几乎没人点明的事实

我们把 t = S 代入看看。也就是说：“稳定性为 S 的卡片，正好在 S 天后再看，会怎样？”

R(S, S) = ( 1 + 19/81 ) ^ (−0.5)
        = ( 100/81 ) ^ (−0.5)
        = ( 81/100 ) ^ ( 0.5)
        = 0.9   ← 正好 90%

这不是巧合。FACTOR = 19/81 和 DECAY = −0.5 正是为了得出这个值而反推出来的常数。 因此，S的真面目可以用一句话来定义。

S（稳定性）=“想起的概率下降到90%所需的天数”
S = 30 的意思是：“30天后再遇到这张卡，十次里能答对九次。” 它不是抽象的内部变量，而是可以用天数来解读的物理量。 SM-2的EF做不到这样的解读。问“EF 2.5”是什么意思，答案只能是“一个用来乘的数”。

改变目标保持率，复习量会如何变化 — 换算表

FSRS允许你直接设定目标保持率（desired retention）（默认0.90）。 把上面的公式对 t 求解，间隔如下。 

间隔 t = S × (81/19) × ( R^(−2) − 1 )

下面是把数字代入这个公式算出的结果。这张表可能是本文最实用的部分。

目标保持率 R间隔（相对 S 的倍数）若是 S=30天 的卡片复习负担
0.95× 0.4614天暴增约2.2倍
0.90（默认）× 1.0030天基准
0.85× 1.6449天减少约40%
0.80× 2.4072天减少约58%
0.70× 4.44133天减少约77%

读法：把保持率从0.90提高到0.95，“只多了5个百分点”，间隔就会缩短到一半以下， 复习量翻倍。反过来，降到0.80时复习量会降到一半以下， 而正确率只损失10个百分点。正因为曲线如此陡峭， “保持率越高越好”的直觉在这里崩塌了。 如果考试不是近在眼前，0.85~0.90 区间通常比较合理。

准确性说明：上述推导以DECAY固定为−0.5的FSRS-4.5 / 5为准。 从FSRS-6开始，DECAY本身也成了需要学习的参数，因此“S = 90%间隔”这个等式 可能不再严格成立。参数个数也随版本从17 → 19 → 21个逐步增加。 请不要在未确认版本的情况下直接引用这些数字。

FSRS做不到的事

FSRS要有你的日志，才会变成属于你的算法。 在复习记录积累到几百到1,000条左右之前，它使用默认参数运行， 而那终究是“别人的平均值”。也就是说，刚开始第一个月的FSRS并没有个性化。 而且留下日志，也意味着所有复习记录都被保存在某个地方。

这里真正该看的数字不是“6次”，而是“33对51”。 三个系统在30天里都让你同样复习了6次。工作量是一样的。 可是莱特纳在第33天再叫你回来，SM-2则在第51天。 同样用掉6次，SM-2却多推远了18天。 这个差距会随着轮次以乘法方式扩大。一年后，莱特纳仍然每16天问你一次， 而SM-2早已达到以年计的间隔。

而且这张表里没有VOCA DECK一栏。因为根本放不进去。 我们的应用根本没有“第几天”这个概念。原因见下一章。

拆解VOCA DECK — 我们的代码实际在做什么

现在轮到我们了。不加包装，照代码原样写出来。

卡片保存的内容：就这些

{ a: "ubiquitous", b: "无处不在的", mem: false }

这就是一张卡片的全部。正面、背面，再加一个布尔值。 复习的时间、错了几次、有多混淆，一概不保存。

所以即使我们想加上SM-2，也加不上。 SM-2至少需要 EF · 重复次数 · 上次复习日， FSRS则必须有完整的复习日志才能拟合参数。 我们没有账号，没有服务器，也没有复习日志。 单词本和已记标记只保存在浏览器的 localStorage 里，不会发送到服务器。 这不是做不出来，而是有意这样做。代价就是放弃个性化。

调度器的真面目：一行取模运算

我们决定“下一张卡”的方式是循环（cyclic）索引。 根据 order 设置分为三种。

设置行为再次相遇的间隔覆盖率
fwd 正向（默认）索引按 +1 循环恰好每 N 张一次（均匀）保证 100%
rev 反向索引按 −1 循环恰好每 N 张一次（均匀）保证 100%
rnd 随机每一步独立均匀抽取
（只排除当前卡）		期望值 N−1 张，
方差大		无保证 ✗
随机模式不是洗牌——这一点我们必须说清楚。
它不是把卡片打乱后走一轮（不放回抽样），而是每次都从其余卡片中重新抽一张。 所以同一张卡可能连续出现三次，也可能整整一轮都不出现一次。

我们把这个代价算成了数字

假设把100张的单词本（N=100）用随机模式跑99步（= 正向一轮的量）。 某张特定卡片在一步中被抽中的概率是1/(N−1) = 1/99。 那么这张卡在99步里一次都不出现的概率是： 

P(出现0次) = (1 − 1/99)^99 ≈ e^(−1) ≈ 0.37

出现次数的分布近似服从泊松分布（λ=1）。

一轮的量（99步）内出现次数概率含义
0次约37%单词本的三分之一整个没出现
1次约37%符合预期
2次约18%浪费
3次以上约8%总是同一张卡

也就是说，用随机模式跑一轮的量，单词本里约37%的卡那天连面都见不着。 跑两轮的量（198步）仍有约13%没出现， 要跑到三轮的量，未出现的比例才会降到5%以下。

所以请这样用（这是从代码推出的处方）
  • 第一遍 · 考前一天全面检查 → 正向。这是需要100%覆盖的时刻。用随机跑会漏掉三分之一。
  • 第三遍之后，需要打破顺序线索时 → 请先用反向。 既打破顺序线索，又保持100%覆盖。大多数人都直接忽略了这个选项。
  • 真正的随机提取训练 → 随机。但要做好把单词本跑三轮的心理准备再用。

时间单位：我们调度器的刻度是“秒”

默认间隔是3秒（控制面板中可设1~60秒）。一张卡要经过正面 · 背面两个阶段，所以 默认是每张6秒。另外计时器设有0.5秒的下限 （无论设得多短，都不会低于这个值）。

由此马上可以得出单词本大小的物理上限。

闪示单词的诚实界限：请把单词本拆分到300张以内。 如果做一个2,000张的单词本，跑一轮要3小时20分钟。 那已经不是“快速重复呈现”了，只是慢吞吞地读列表。 如果你需要管理2,000张卡，那是Anki的工作，不是这个应用的工作。

间隔就是“提取窗口”的长度 — 请非对称地设置

如果只把间隔当作“速度调节”，那你只用到了一半。 正面停留在屏幕上的那几秒，是你努力回想答案的唯一时间。 所以我们让正面和背面的间隔可以分别设置（高级设置，0~60秒）。

情况正面间隔背面间隔每张意图
第一遍（满是不认识的单词）2秒4秒6秒没什么可回想的，所以多看一会儿词义
第2~3遍（提取训练）5秒1.5秒6.5秒争取回想的时间，确认一闪而过
考前冲刺1.5秒1.5秒3秒全面扫描 — 100张5分钟过完
TTS 听觉学习3秒3秒6秒留出语音播完的时间

第2~3遍的“正面5秒 / 背面1.5秒”是本应用中最接近提取练习的设置。 遍数越往后，越要延长正面、缩短背面。 大多数人正好反过来，结果从头到尾都只是被动地看。

“已记标记”的真面目 — 只有2个盒子的莱特纳

我们唯一的个性化机制只有一个：已记标记。 把它翻译成算法语言，确切地说就是这样。

已记标记 = 只有2个盒子的莱特纳盒。不过它不是梯子，而是一扇门。
盒子1 = mem: false（持续循环）· 盒子2 = mem: true（从循环中排除）
而显示范围设置用来选择盒子 — 排除已记（默认）/ 仅已记 / 全部。

仅凭这一点能得到什么（比你想的多）

个性化算法所做的事情里，最大的一块其实是“不给你看已经会的卡”。 SM-2把EF 2.5的卡推到587天后，归根结底也是为了现在不给你看。 已记标记拿到的是这个效果中最粗暴、但也最大的那一块。

用数字来看。在100张的单词本中给40张打上已记标记，参与循环的就剩60张。 一轮从10分钟 → 6分钟，不会的卡的再次相遇间隔也从10分钟 → 6分钟。 同样花20分钟，遇到难卡的次数变成了1.67倍。 白白得来的1.67倍。只凭一个复选框。

与真正的SM-2相比欠缺的地方（这里很重要）

① 没有等级——非0即1。 SM-2会区分“EF 2.5（非常简单）”“EF 1.6（有点难）”和“EF 1.3（地狱）”， 并以各自不同的频率呈现。我们只有“看 / 不看”两种。 在还没记住的60张里，所有卡都完全平等。 昨天第一次见的单词，和看了40遍都记不住的单词，会以完全相同的频率出现。 这是我们输给SM-2最明显的地方。

② 没有时间——所以无法计算“什么时候再看”。 mem 是布尔值。我们不保存你是什么时候标记的。 所以“这张卡标记已经40天了，该再确认一下了”这种判断， 应用从原理上就做不到。因为没有时间戳。

③ 由此产生的盲区——被标记的卡会悄悄腐烂。

这是本文最重要的警告。
已记标记是一扇单向门。卡片一旦去了盒子2， 就没有自己回来的路。 SM-2即使是587天的卡，总有一天也一定会再叫回来——为了抓住遗忘。 我们则永远不会叫回来。
也就是说，“标记为已记的卡其实已经忘了，而你却不知道”的状态会不断累积。 然后你会在考场上才发现。

手工填补这个盲区的步骤

算法不帮你做，就只能由人来做。幸好并不难，应用里也已经有这个功能。 把显示范围切换为“仅已记”，正是为了这个用途而存在的。

  1. 每周一次，定好日子。（例：星期日）
  2. 把显示范围切换为“仅已记”。→ 只有打了已记标记的卡参与循环。
  3. 顺序设为随机，正面间隔调长到4~5秒。——这是在测试真正的提取。
  4. 遇到想不起来的卡，当场取消已记标记。→ 降级到盒子1。这是在亲手为它打开回来的门。
  5. 再切回“排除已记”，照常运行。

这5个步骤，就是手动模仿SM-2“成熟卡片复习”的全部内容。 因为不是自动的，所以较差，但比什么都不做要好得多。 如果不做这件事，已记标记就会变成“把假装会的卡藏起来的功能”。

最准确的答案：两者处于不同的层次

读到这里，下面这句话你应该能理解了。

Anki决定“今天看哪些卡”。（以天为单位）
闪示单词决定“现在如何呈现这些卡”。（以秒为单位）
两者不是在为同一个问题争斗，而是上下叠加在一起。

同时使用两者的人实际采用的组合如下。

  1. 长期计划交给Anki。5,000词的牌组中“今天要看的120张”由FSRS帮你挑出来。
  2. 把在Anki里反复答错的卡（难记卡、ease接近1.3的卡）导出为CSV。 通常会有30~80张。
  3. 把这个CSV放进闪示单词，每天跑两三轮。 80张的话一轮8分钟。正面5秒 / 背面1.5秒，做提取练习。
  4. 在闪示单词里已经牢固的卡，用已记标记移出，并在Anki里重置那张卡的ease。

Anki做不到的由闪示单词来做，闪示单词做不到的由Anki来做。 Anki做不出单次学习内的高密度呈现（它不会一天给你看同一张卡20次）， 闪示单词则算不出6个月后的复习日。 一个文件（CSV）就把两个工具连接起来。 制作方法见制作CSV单词本。

简短问答 Q&A

Q. FSRS总是比SM-2好吗？

在积累了足够的复习日志之后，大体如此。但刚开始的第一个月并不是。 FSRS要用你的日志拟合参数后才属于你，在那之前它用的是别人的平均值。 而且FSRS建立在你会诚实按按钮的假设之上。 如果你随手只按Good，精巧的算法就会精巧地出错。 垃圾进，垃圾出——这是算法无法替你修正的。

Q. 目标保持率设成多少合适？

请再看一遍上面的换算表。0.90 → 0.95 会让复习量翻倍。 为了买5个百分点的正确率，要付出两倍的时间。大多数情况下是亏的。 考试还远就设0.85~0.90，考试近在眼前就设0.90~0.95，这是比较合理的起点。 不过，这只是“起点”，不是“正确答案”。

Q. 闪示单词的间隔设几秒合适？

“合适的值”每一遍都不同。默认的3秒只是适合第一遍的稳妥值。 遍数越多，越要延长正面（回想的时间）、缩短背面（只用来确认）。 正面5秒 / 背面1.5秒是最接近提取练习的设置。 详细的配置见上面的表。

Q. 随机模式不是总比正向好吗？毕竟能打破顺序线索。

不是，这正是本文算出来的陷阱。随机不保证覆盖率 （一轮的量里约37%不出现）。如果既想打破顺序线索又想保住覆盖率， 请用反向。大多数用户都不知道这个选项为什么存在。

Q. 全部打上已记标记后单词本空了。这就算结束了吗？

不。从那时起才是开始。请把显示范围切换为“仅已记”， 每周检查一次。想不起来的卡请取消标记，让它回去。 如果不做这个步骤，已记标记就会变成掩盖遗忘的功能。步骤写在上面。

Q. 那VOCA DECK将来会加入SM-2吗？

要加入，就得保存复习日志；这样存储会变大，就会想要跨设备同步， 然后就需要账号。那一刻，这个应用唯一的优点“零摩擦”就消失了。 那等于把Anki重做成一个更差的版本。 我们并不想成为Anki。目前没有加入的计划， 不加入的理由已经贯穿写在整篇文章里了。

最后 — 算法管不到你打开应用这一步

FSRS是世界上最好的调度器。但如果你3天不打开应用，它就什么都不是。 它只是按完美的间隔摆出“今天要复习的卡340张”等着你， 而看到这个数字的人会关掉应用。

间隔重复算法50年的历史，是一场“把复习降到最少的竞赛”。 莱特纳靠5个格子，SM-2靠EF乘法，FSRS靠你的日志。 大家朝着同一个目标——删掉不必要的复习。

可是，人们真正失败的地方并不在那里。 人们不是因为“复习太多”而放弃，而是因为“今天没打开”而放弃。 这就是我们整个放弃个性化、把一切押在把摩擦降到零上的原因。 我们并不确定这是正确的选择。 但这是我们做出的选择，而它的代价，我们在本文中一点也没有隐瞒。
