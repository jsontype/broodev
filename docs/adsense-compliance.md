# AdSense 심사 통과 기준 · 준수 현황

> **목적** — broodev.com 이 Google AdSense "가치가 별로 없는 콘텐츠"로 **두 번** 탈락한 뒤,
> 관련 Google 정책 전문을 항목별로 대조하고 **무엇을 어떻게 고쳤는지**를 증거와 함께 기록한다.
> 재심사 전 체크리스트이자, 앞으로 새 앱을 만들 때 지켜야 할 규칙이다.
>
> 최종 갱신: 2026-07-14 · 대상: `broodev.com`(루트=코인 시그널), `voca.broodev.com`

## 0-A. ⚠️ 2026-07-15 전수 감사 — 이전 판의 주장 중 상당수가 틀렸다

7개 렌즈 병렬 감사에서 **79건**이 나왔다(CRITICAL 16 · HIGH 27). 이 문서의 이전 판이
**"광고 게재 화면은 btc·voca 2개뿐"** 이라고 단언했는데 **거짓이었다.**
로더 스크립트(`googlesyndication`)만 grep 했고, **렌더링되는 `<ins class="adsbygoogle">` 태그와
`ads.txt` 를 확인하지 않았다.**

### 이번에 잡아낸 것 중 가장 심각했던 것들

| 문제 | 실체 |
| --- | --- |
| **가짜 계산 게이트** | 데이터를 이미 다 받아놓고 **6~9초 가짜 "계산 중" 연출**(`total = 6000 + rand(3000)`)을 돌렸다. UI 문구가 13개 언어 전부에서 **"그동안 아래 광고가 노출됩니다"** 라고 명시. 코드 주석이 스스로 **"연출"** 이라 불렀다. STALE 되면 점수를 다시 잠가 **게이트 반복 통과**(= 광고 반복 노출). → **광고 노출을 인위적으로 만드는 장치.** 전면 삭제 |
| **광고 화면 ≠ 콘텐츠 화면** | 원본 콘텐츠 12편을 썼는데 **그 페이지엔 광고가 없었다.** AdSense 가 심사하는 "광고가 게재되는 화면"은 여전히 대시보드 하나뿐이었다. → **콘텐츠 페이지 18장에 AdSense 추가.** 이제 광고 화면 = 콘텐츠 화면 |
| **빈 광고 슬롯** | `data-ad-slot=""` 로 600px "AD" 라벨 빈 박스 2개를 렌더 + `***! TODO` 주석과 `여기에_광고단위_슬롯ID` 플레이스홀더가 view-source 에 그대로 노출 → **미완성 화면.** RailAd·플레이스홀더 전부 삭제 |
| **클론 "광고 제거"가 미완** | 로더만 지웠고 `<ins data-ad-client="ca-pub-…">` 는 여전히 렌더됐다. **`ads.txt` 19개**가 pub ID 를 선언 중이었다 → 클론 콘텐츠 **전부 삭제** + 301, `ads.txt` 는 btc·voca 만 |
| **`renderSEO()` 가 내부링크를 지움** | 언어 전환 시 `section.seo` 를 통째로 덮어써서 **새로 추가한 콘텐츠 링크가 사라졌다** → `build()` 에 링크 블록 추가 |
| **`dev` 가 코인 클론을 다시 링크** | 통합 sed 가 `app.jsx` 를 놓쳐 dev 포털이 14개 클론을 전부 링크 중이었다 → 루트 `?coin=` 로 교체 |
| **soft-404** | 존재하지 않는 URL 전부가 **HTTP 200 + 광고 붙은 홈페이지**를 반환 → `404.html` + `_redirects` 로 진짜 404 |
| **크롤 차단 함정** | `admin` 의 `robots.txt Disallow: /` 가 크롤을 막아 **noindex 가 영영 적용되지 않음**(색인에서 안 빠짐) → `Allow: /` 로 수정. 코인 클론도 같은 이유로 `Allow`(301 을 크롤러가 봐야 통합됨) |
| **내부 문서 공개 서빙** | `broodev.com/README.md` 로 내부 TODO·**프리미엄 우회 치트**가 공개되고 있었다 → 배포 디렉터리에서 삭제 |

> **교훈: `index.html` 만, 로더 스크립트만 grep 하지 마라.**
> **모든 `*.html`** 에서 **렌더링되는 광고 마크업(`<ins>`, `data-ad-client`)과 `ads.txt`** 까지 봐야 한다.

## 2. 중복 콘텐츠 없음

> **Google:** "독창적이거나 가치 있는 콘텐츠를 추가하지 않고 다른 사이트의 콘텐츠를 복사하여 다시 게시하는 사이트"
> "**동의어로 대체하거나 자동화된 기법을 사용하는 등의 방법으로 다른 사이트의 콘텐츠를 복사하여 약간 수정한 후 다시 게시하는 사이트**"
> "여러 페이지가 유사하거나 매우 유사한 콘텐츠가 많은 경우 각 페이지를 확장하거나 **하나로 통합**하는 것이 좋습니다."
> "동일한 페이지 내에서 또는 **사이트의 여러 페이지 전반에서 동일한 콘텐츠가 중복되지 않도록** 합니다."

### 이것이 우리의 실제 탈락 사유였다
코인 15종을 **코인 이름만 치환**해 양산한 것이 정확히 위 문구에 해당한다.

### 조치 — 15개 → 1개로 통합
Google 이 권고한 **"하나로 통합"** 을 그대로 실행했다.

| 항목 | 이전 | 현재 |
| --- | --- | --- |
| 색인되는 코인 페이지 | **15개** (91% 동일) | **1개** (루트) |
| 광고 게재 코인 페이지 | **15개** | **1개** (루트) |
| 코인 전환 방식 | 서브도메인 복제본 15개 | **한 앱 안의 파라미터** `broodev.com/?coin=eth` |
| 클론 간 상호링크 | 각 클론이 14개 형제를 링크 | **전부 제거** |

- 루트 `apps/btc` 에 **코인 레지스트리(15종) + 선택기** 추가 → 앱 하나가 전 코인 서빙
- 코인 서브도메인 14개: **AdSense 제거** + `noindex` + `canonical→루트` + `sitemap.xml` 삭제 + 상호링크 제거
- 코인 클론의 `privacy/terms` 28장도 `noindex` (본체는 noindex 인데 하위 정책 페이지만 색인되던 문제)

### 추가로 잡아낸 중복 (전수 감사에서 발견)
- **`apps/btc/adsense/`** — 루트의 **구 광고버전 고아 폴더**. `broodev.com/adsense/` 로 **실제 라이브 서빙 중**이었고
  **광고 게재 + `index,follow` + canonical 이 낡은 `btc.broodev.com`** 이었다.
  즉 구글에게 **루트와 동일 콘텐츠의 광고 페이지가 2장** 보이고 있었다.
  → 광고 제거 + `noindex,nofollow` + canonical→루트
- **`apps/voca-backup/`** — voca 와 89% 동일한 롤백 스냅숏이 광고+색인 상태 (현재 DNS 미배포)
  → 광고 제거 + `noindex` (배포되어도 안전하도록)
- **`apps/btc/member/`** — canonical 이 낡은 서브도메인 → 루트로 교체

> ⚠️ **`noindex` 만으로는 AdSense 가 해결되지 않는다.**
> `noindex` 는 **검색 색인** 지시일 뿐이고, AdSense 정책은 **광고가 게재되는 화면**에 적용된다.
> **광고 재고에서 빼는 것(스크립트 제거)** 이 실질적 조치다. 둘 다 했다.

### 🔴 아직 남은 것 — 배포 시 반드시
Google 스팸 정책은 **"쿠키 커터"** 접근을 명시적으로 금지한다. 클론이 **존재하는 한** 위험이 남는다.
→ **Cloudflare 에서 `<coin>.broodev.com` → `broodev.com/?coin=<coin>` 301 리다이렉트** 로 완전 소멸시킬 것.
(절차: [`deploy-cloudflare.md`](deploy-cloudflare.md) §1-C)

## 3. 탐색 요소 · 사용자 환경

> **Google:** "만족스러운 사용자 환경을 제공하려면 **쉽게 찾고 사용할 수 있는 탐색 메뉴(메뉴 바)** 를 갖추는 것이 중요합니다."
> "**메뉴 바에 탐색 요소를 추가하고 주제별, 카테고리별로 콘텐츠를 구성**하면 사용자가 내 사이트를 파악하고 탐색하는 데 도움이 됩니다."
> 점검 항목: 정렬(모든 기기) · 가독성 · 기능(클릭 가능) · **정확성(알맞은 콘텐츠로 연결)**

### 조치 — 탐색 메뉴 신설
**이 요건은 전수 감사에서야 발견됐다.** 그전까지 콘텐츠 링크가 **푸터에만** 있었고 메뉴 바가 없었다.

- `broodev.com` 상단에 `<nav class="site-nav">` 추가: **대시보드 · 점수 방법론 · 지표 해설 · 공포지수 활용법 · 용어집**
- `voca.broodev.com` 상단에 추가: **암기장 · 암기법 원리 · CSV 만들기 · 학습 전략**
- 콘텐츠 페이지 7편에도 각각 상단 내비 존재
- `#root` **바깥**에 두어 React 렌더·언어 전환에도 사라지지 않고, **JS 없는 크롤러도 읽는다**
- 모바일 대응(`@media max-width:560px`), `aria-label`/`aria-current` 접근성 속성 포함

**정확성 검증:** 메뉴의 모든 링크가 실존 파일을 가리킴 (자동 검사 통과, 깨진 링크 0)

### 그 외 요건
- ✅ **누락된 페이지로 연결되는 링크 없음** — 내부 링크 전수 검사 통과
- ✅ **여러 브라우저 표시** — 표준 HTML/CSS, CDN React. 반응형
- ✅ **사이트 테마와 무관한 페이지 없음** — 코인 시그널 / 단어암기로 주제 일관

## 4. 클로킹 · 부적절한 리디렉션

> **Google:** "클로킹이란 Googlebot 에 제공되는 콘텐츠와 사용자에게 제공되는 콘텐츠가 다른 경우를 말합니다."
> "조건적으로 리디렉션하는 URL이 있는지 확인합니다. 이 유형의 리디렉션은 주로 **자바스크립트**로 작성됩니다."
> "**구독 및 페이월 콘텐츠**: 게시자는 Google에서 페이월 콘텐츠와 클로킹 행위를 구분할 수 있도록 **페이월 콘텐츠를 구조화된 데이터에 포함**해야 합니다."

### 검증 결과

| 항목 | 상태 | 증거 |
| --- | --- | --- |
| 정적 SEO 본문이 사용자에게도 보이는가 | ✅ **보임** | `.seo { position:relative; z-index:2; ... }` — `display:none` 아님. 크롤러와 사용자가 같은 것을 본다 |
| CSS 로 숨긴 키워드 텍스트 | ✅ **없음** | `visibility:hidden` 은 **호버 툴팁(`.tip`)** 에만 적용 — 정상 UI 패턴 |
| 배경색과 같은 색 텍스트 | ✅ 없음 | |
| 조건부 JS 리디렉션 | ⚠️ **존재** | `apps/btc/index.html`: `localStorage.getItem('btc:member')==='1' → location.replace('member/')` |
| 페이월 구조화 데이터 | ⚠️ **주의** | `apps/voca`: `"isAccessibleForFree": true` — 현재 `PREMIUM.launch = false` 라 **사실과 일치**함 |

### ⚠️ 조건부 리디렉션에 대한 판단
btc 의 `member/` 리디렉션은 **이용자가 스스로 `?member=1` 로 설정해야만** 발동한다.
Googlebot 과 **일반 신규 방문자는 동일한 페이지**를 본다 → 전형적 클로킹은 아니다(페이월 동작에 가깝다).
`member/` 는 `noindex, nofollow` 이고 광고도 없다.

**그러나 리스크는 남는다:**
- 이 기능은 **미완성**이다 (코드 주석: `***! TODO: 실제 구독 검증은 결제+인증 백엔드로. 지금은 임시 클라이언트 플래그(우회 가능, 보안 아님)`).
- AdSense 는 **"아직 미완성 상태인 화면"** 도 금지한다.

**권고 (택1):**
1. **결제/구독을 실제로 출시하기 전까지 `member/` 리디렉션을 비활성화**한다. (가장 안전)
2. 유지한다면 **페이월 구조화 데이터**(`isAccessibleForFree: false` + `hasPart`/`cssSelector`)를 추가하고,
   `voca` 의 `isAccessibleForFree` 도 프리미엄 출시 시 **반드시 함께 갱신**한다.

### 이미지 클로킹 · 모바일 리디렉션
- ✅ **이미지 클로킹 없음** — 사용자와 검색결과에 동일 이미지. `functions/_middleware.js` 는 `?lang=` 에 따라 OG 메타를 바꾸지만, **같은 URL 이면 누구에게나 같은 응답**이라 클로킹이 아니다.
- ✅ **모바일 전용 리디렉션 없음** — user-agent 기반 분기 없음.
- ⚠️ 코인 클론들의 OG 썸네일이 btc 것 복사 상태 (README TODO). 301 로 클론을 없애면 자연 해소.

## 9-B. 실전 운영 관점 (현장 경험칙 대조)

### ① 색인 페이지 수 — **한 자릿수면 그 자체가 탈락 사유**
Search Console 의 색인 페이지 수가 한 자릿수면 Google 이 "이 사이트를 파악할 만큼의 콘텐츠가 없다"고 본다.

| 시점 | `broodev.com` 색인 가능 페이지 |
| --- | --- |
| 탈락 당시 | **3** (index + privacy + terms) ← 한 자릿수. **이것이 핵심 원인 중 하나였다** |
| 콘텐츠 4편 추가 후 | **7** ← 여전히 한 자릿수 |
| 심층 해설 6편 추가 후 | **13** ← 두 자릿수 진입 |

> ⚠️ **역설:** 코인 15→1 통합은 중복 위반을 없앴지만 **색인 페이지 수를 줄였다.**
> 그래서 **서로 진짜 다른** 심층 콘텐츠로 페이지 수를 다시 늘려야 했다.
> **템플릿 양산으로 페이지 수를 늘리는 것은 우리를 죽인 그 실수의 반복이다.** 절대 금지.

**재심사 전 반드시:** Search Console → 색인 생성 → **색인된 페이지 수 확인**.
Google 이 구체적 탈락 사유를 주지 않으므로 **이것이 유일하게 얻을 수 있는 실제 데이터다.**

### ③ 재심사 간격 — **2주 ~ 1개월**
> **아무것도 고치지 않고 재신청하면 자동으로 같은 사유로 또 떨어진다.**
> 더 중요한 것: **고쳤더라도 Google 이 재크롤하기 전에 신청하면 Google 은 옛날 상태를 본다.**

4. **그 다음에** 재심사 요청

### ④ 프로그래매틱 페이지 — noindex 후 승인되면 해제? **우리는 예외다**

일반적으로는 정석이다: 프로그래매틱 페이지에 승인 전 `noindex` 를 걸고, 승인 후 해제한다.
**그러나 그것은 각 페이지가 진짜로 고유한 가치를 가질 때의 이야기다.**

**우리 코인 클론 14개는 91% 동일하다.** 승인 후 `noindex` 를 풀면:
- 91% 동일한 페이지 14개가 다시 색인 → **탈락했던 상태로 정확히 복귀**
- AdSense 는 **승인 후에도 지속적으로 단속**한다 → 나중에 정책 조치(수익 중단) 위험
- Google 웹검색 스팸 정책의 **"쿠키 커터"** 에 그대로 해당

**따라서 선택지는 둘뿐이다:**

| 선택 | 내용 | 결과 |
| --- | --- | --- |
| **A (권장)** | 복원하지 않는다. **301 로 루트에 영구 통합** | 안전. 코인 롱테일 SEO 는 포기 |
| **B** | **코인마다 고유 콘텐츠를 붙인 뒤** 복원 | 각 코인별 고유 해설/논평/데이터 분석이 있어야 "합법적 프로그래매틱"이 된다. 그때는 `noindex` 해제가 정당 |

> **`noindex` 해제는 콘텐츠를 채운 다음에나 꺼낼 수 있는 카드다.**
> 지금 상태로 해제하면 재발한다.

## 9-C. 🔴 레포에서 못 고치는 것 — 반드시 Cloudflare 에서 처리할 것

아래는 **코드로 해결이 안 되고 Cloudflare 콘솔에서 처리해야 하는 잔여 위험**이다.
배포만 하고 이걸 안 하면 **여전히 탈락 사유가 남는다.**

### ① `btc.broodev.com` — 통합에서 누락된 15번째 클론 🔴
`apps/btc` 한 디렉터리가 **`broodev.com` 과 `btc.broodev.com` 두 호스트에 동시 배포**된다
(`broodev-web` + `broodev-btc` 두 Pages 프로젝트). 즉 심사 대상 루트의 **완전 복제본**이
광고를 달고 살아 있다. `_redirects` 로는 못 고친다 — 같은 파일이 양쪽에 배포되므로
`_redirects` 를 넣으면 루트까지 리다이렉트된다.

**조치 (택 1)**
- **(권장) `broodev-btc` Pages 프로젝트를 삭제**하고 `btc.broodev.com` DNS 레코드를 제거한다.
- 또는 Cloudflare → `broodev.com` 존 → **Rules → Redirect Rules**:
  `Hostname equals btc.broodev.com` → `https://broodev.com/` **301**

### ② `*.pages.dev` 프리뷰 도메인 🔴
Pages 프로젝트마다 `broodev-web.pages.dev` 같은 **크롤 가능한 사이트 복제본**이 하나씩 더 있다.
**조치:** 각 Pages 프로젝트 → Settings → **Preview deployments 접근 제한**, 또는
Cloudflare Access 로 `*.pages.dev` 를 잠근다.

### ③ 코인 서브도메인 301 확인
레포에 `apps/<coin>/_redirects` (`/* https://broodev.com/?coin=<coin> 301`) 를 넣었다.
`robots.txt` 는 **`Allow: /`** 로 두었다 — **크롤이 막히면 Google 이 301 을 못 보고 색인에서 안 빠진다.**
**배포 후 반드시 확인:** `curl -I https://eth.broodev.com/` → `301` + `Location: https://broodev.com/?coin=eth`

### ④ 배포 watch path
`apps/web` 은 레포에서 사라졌는데 `broodev-web` 프로젝트의 **Root directory 가 아직 `apps/web`** 이면
빌드가 실패하거나 옛 버전이 계속 서빙된다.
**조치:** `broodev-web` → Settings → **Root directory = `apps/btc`** 확인.

### ⑤ (보안) `voca.broodev.com` 공개 이미지 업로드 API
`apps/voca/functions/api/shot.js` 는 문의 폼 스크린샷용인데 **Origin/Referer 헤더 검사만** 한다.
헤더는 위조 가능하므로 **누구나 광고 게재 도메인에 임의 이미지를 호스팅**할 수 있다
(2MB 제한 · 이미지 타입 검사 · 90일 TTL 은 있음).
**조치:** Cloudflare **Turnstile** 또는 Rate Limiting 을 붙이거나, 문의 폼에서 업로드를 제거한다.

## 10. 앞으로의 규칙 (같은 실수 반복 금지)

> **README 에 "양보다 질 — 스팸성 양산이 아니라"라고 써두고 정확히 그 반대를 했다.**
> 이 규칙은 문서가 아니라 **강제 사항**이다.

1. **같은 앱을 파라미터만 바꿔 복제하지 않는다.**
   변형은 **한 앱 안의 옵션**(`?coin=`)으로 처리한다. 새 서브도메인은 **본질적으로 다른 기능**일 때만.
2. **얇은 페이지에 광고를 붙이지 않는다.**
   광고를 달려면 그 화면에 **고유한 게시자 콘텐츠**가 있어야 한다. 없으면 광고를 빼거나 콘텐츠를 채운다.
3. **광고 게재 화면은 `index.html` 만이 아니다.**
   `member/`, `adsense/`, 백업 폴더까지 **모든 `*.html` 을 전수 검사**한다.
   (과거 감사가 `index.html` 만 봐서 `btc/adsense/` 고아 광고 페이지를 놓쳤다)
4. **백업·스냅숏 폴더는 즉시 `noindex` + 광고 제거.** 배포되는 순간 복제 콘텐츠가 된다.
5. **새 앱에는 처음부터** 탐색 메뉴 · 개인정보처리방침 · 연락처 · 원본 콘텐츠를 갖춘다.

## 부록 A. 검증 방법 (재현 가능)

```bash
# 광고가 게재되면서 색인되는 모든 화면 (index.html 만이 아니라 전체 HTML)
find apps -name '*.html' | while read f; do
  grep -q 'googlesyndication' "$f" || continue
  grep -q 'content="noindex' "$f" && continue
  echo "광고+색인 → $f"
done
# 기대 결과: apps/btc/index.html, apps/voca/index.html — 이 둘만

# 색인되는 코인 페이지 (루트 1개여야 함)
for c in btc eth xrp doge bch link xlm ltc avax shib dot pepe grt sand mana; do
  grep -q 'content="noindex' apps/$c/index.html || echo "색인: $c"
done

# 낡은 canonical 잔존 확인 (0건이어야 함)
grep -rl 'canonical" href="https://btc\.broodev\.com' apps

# 인브라우저 JSX 가 실제로 컴파일되는가 (실패 시 사이트가 백지가 된다)
npm i @babel/standalone
node -e "const B=require('@babel/standalone'),fs=require('fs');
const h=fs.readFileSync('apps/btc/index.html','utf8');
B.transform(h.match(/<script type=\"text\/babel\"[^>]*>([\s\S]*?)<\/script>/)[1],{presets:['react']});
console.log('JSX 컴파일 OK')"
```
